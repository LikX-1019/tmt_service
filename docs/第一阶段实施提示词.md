## API 契约

请求：

```http
POST /api/v1/chat
Content-Type: application/json

{"message": "你好"}
```

成功响应：

```json
{"code": 0, "message": "success", "data": {"answer": "..."}}
```

`message` 去除首尾空白，长度为 1～4000。参数错误返回 HTTP 422 和统一 envelope；
模型异常返回 HTTP 502、`LLM_INVOCATION_ERROR`，不得向客户端暴露 traceback。

## 日志硬性验收

1. 每个进程生成 `logs/app-YYYYMMDD-HHMMSS-PID.log` 和
   `logs/error-YYYYMMDD-HHMMSS-PID.log`。
2. 日志采用 UTF-8 JSON Lines，至少含毫秒时间、级别、logger、消息、源码绝对
   文件名、行号、函数名和 request_id。
3. HTTP 日志额外含 method、path、status_code、duration_ms；响应头回传
   `X-Request-ID`。
4. `logger.exception` 的错误记录保留完整堆栈；error 文件只保存 ERROR 及以上，
   使错误可从单个文件直接定位。
5. 不记录 API Key、Authorization、完整请求体或完整用户消息。
